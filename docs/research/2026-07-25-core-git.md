# F080 Core Git workflow

日期：2026-07-25

## 目标与边界

`F080` 五条 acceptance：status/diff/hunk stage/commit/fetch/pull/push 工作；Git 输出解析 locale 无关；未信任 workspace 绝不启动 Git 或配置的 helper 进程；后台读不得执行 hooks/fsmonitor/external diff/textconv/credential helper；破坏性动作预览影响 + 二次确认。遵循 ADR 0003（系统 Git CLI 为写权威、不混 git2/gix、禁任意 `git_run`、hardened background mode）。GitLens-like 增强中「历史只读」（blame/history/graph/compare/refs/stash/worktree）归 F090；GitKraken 账号/云/AI/品牌明确排除。真实桌面场景登记交接清单。

## 调研结论（双路 + 仓库审计交叉，锚定 Code OSS `5264f`、v35.0.1）

### 产品边界（决定性，S1 级）

- `@codingame/monaco-vscode-scm-service-override@35.0.1` 存在，注册 `ISCMService`/`ISCMViewService`/`IQuickDiffService`/`IQuickDiffModelService`/`IGitService`，并静态 import 执行 `scm.contribution.js`（SCM viewlet/资源组/输入框/菜单全靠它）。
- **`scm.contribution.js` 无条件 import + `registerWorkbenchContribution2` 注册 `SCMHistoryItemContextContribution`，它注入 `IChatContextPickService` 为必需依赖**——不装 chat override 会在贡献实例化阶段崩溃（功能阻断，非仅政策）；`scmInput.js` 另挂 AI 生成 commit message/AI 解冲突按钮（`ChatContextKeys`/`product.defaultChatAgent`）。CodinGame demo 的 scm/chat override 始终成对安装，从未验证「只 SCM 不 Chat」。
- 官方自定义 SCM provider 的纯 service seam 是 `ISCMService.registerSCMProvider(provider)` + `IQuickDiffService.addQuickDiffProvider(...)`（不经扩展宿主，与 PlainSearchService 先例一致）；demo 走的 `vscode.scm.createSourceControl` 是扩展 API 路径，Plain 禁用。
- 仓库审计发现的**排除面缺口**：`excluded-surfaces` 快照只有 command/viewContainer/view 三维，**无 contributionIds 维度**；六类正则只兜 chat/agent/copilot/mcp 字样，对 `generateCommitMessage` 这类不含 chat 字样的真实 AI 命令**无覆盖**（product-scope 已列「不做 AI commit message」但无机器兜底）。

### 上游 Git 命令参考（extensions/git，Plain 自建 Rust 不照抄扩展）

- spawn 固定 `LANG/LC_ALL=en_US.UTF-8`（locale 无关）、参数数组、无 shell 拼接。
- 关键偏离参考：上游 `status -z -uall` 用短格式，Plain 按 ADR 升级为 `--porcelain=v2 -z --branch`（一次拿 branch/ahead-behind/rename score）；上游 diff 主动 `--textconv` 渲染，Plain 后台读必须 `--no-textconv --no-ext-diff`（ADR 硬化）。
- **hunk stage 架构**（可直接复用）：上游不用 `git apply --cached`，而是前端 Monaco diff 引擎算出「应用选中 hunk 后的完整文件内容」→ `git hash-object --stdin -w --path <rel>` 生成 blob → `git update-index --cacheinfo <mode> <hash> <rel>` 写索引。Plain 前端用 Monaco diff 算新内容，Rust 只需这两条命令，无需自写 patch 应用。
- commit：`git -c user.useConfigOnly=true commit --quiet --file -`（message 走 stdin）。blame：`git blame --root --incremental`（F090）。log：固定 `%H%n%aN%n...%B` format + `-z`。

### 地基（仓库审计）

- trust 门 `TrustService::require_trusted`（F070）已泛化并在 terminal 域端到端验证，模块文档点名供 Git 复用；git spawn 逐字复用同一前置。
- spawn guard `SPAWN_GUARDED_DOMAIN_PATTERN` 已覆盖 `src-tauri/src/git/*.rs`，但**报错文案硬编指向 PTY 的 `portable_pty::CommandBuilder`**，与 git 非交互一次性捕获模式不匹配，需修订为 git 专用受限封装。
- `FORBIDDEN_SPAWN_BYPASS_DEPENDENCIES` 已禁 async-process/duct 等，但**无 git2/gix 机器禁令**（仅文档约定）。
- Monaco Diff Editor 核心 widget 已随 `monaco-vscode-editor-api` 可用（并排 diff 不需新 override）；多文件 diff（commit 详情）走独立 `multi-diff-editor-service-override`，延后 F090。
- IPC 范式：status/diff/blame 走一次性 request-response（trust 命令先例）；log 走分页/有界事件流（架构文档已点名复用 search/terminal 先例）。git 状态刷新需 git 域自建 `.git` watcher（workspace watcher 是私有实现，不直接复用）。

## 技术方案

### 决策 1：SCM override 引入 + AI 剥离（vendor patch，含回退）

- 安装 `@codingame/monaco-vscode-scm-service-override@35.0.1`，**新增第 5 份可审计 pnpm patch**：物理删除 `scm.contribution.js`/`scmInput.js` 中对 `scmHistoryChatContext`/`ChatContextKeys`/`CHAT_SETUP_SUPPORT_ANONYMOUS_ACTION_ID` 的静态 import、`registerWorkbenchContribution2(SCMHistoryItemContextContribution...)` 注册、及 AI commit/conflict 按钮分支。patch 纳入既有 workbench-patch-contracts Harness（SHA/hunk 锁定）。`IGitService` 死注册登记进债务清单不处理。
- **回退**：若 patch 因上游结构难以稳定剥离，改方案②——不消费官方 `scm.contribution.js`，只 import 具体类（ISCMService/SCMService/SCMViewService/IQuickDiffService）自建无 AI 的 view container 注册（search/terminal 自建先例）。实施中判定，报告选择。

### 决策 2：排除面纵深加固（先于引入 override）

- 给 `excluded-surfaces` 快照增 **contributionIds 维度**（捕获 `registerWorkbenchContribution2` 的 id）；给排除正则增 AI 语义覆盖（`generateCommitMessage`/`chat`/`copilot` 之外的 AI 命令名模式），使即便 patch 漏剥也被运行时 guard 拦截 bootstrap。belt-and-suspenders：patch 移除 + 运行时 guard 双保险。

**收窄记录（S0 落地后实测暴露的范畴错误，如实记录，非事后包装）**：contributionIds 维度上线后，全量 Playwright 实测 **62 failed / 1 passed**，bootstrap 直接抛出
`PLAIN_EXCLUDED_SURFACE_GUARD_V1: contributionIds:workbench.contrib.colorExtensionPoint (extensions, gallery or marketplace), contributionIds:workbench.contrib.iconExtensionPoint (同上), contributionIds:workbench.contrib.jsonValidationExtensionPoint (同上), contributionIds:workbench.contrib.statusBarItemsExtensionPoint (同上), contributionIds:workbench.contrib.tokenClassificationExtensionPoint (同上), contributionIds:workbench.contrib.viewsExtensionHandler (同上), contributionIds:workbench.contrib.recentRemoteFolderPruner (remote development or tunnels)`
（真实捕获于 `test-results/foundation-boots-the-allow-092cb-t-excluded-runtime-surfaces/error-context.md`，非合成用例）。根因是**范畴错误**：六类排除正则是为「用户可见的 command id / view id」设计的，contributionIds 是**内部管道命名空间**——上面 7 个 id 逐一核对过 `node_modules` 内 `@codingame/monaco-vscode-api@35.0.1` 与本项目实际依赖的 `monaco-vscode-configuration-service-override` 源码，确认它们是 `AGENTS.md` 明确允许的「惰性静态 contribution/extension-point registry」本身（主题系统的 color/icon/tokenClassification extension point、status bar API 的 extension point、views extension handler；`recentRemoteFolderPruner` 是「最近打开工作区」MRU 清理，与 Remote Development 功能面无关），不是扩展市场/Remote Dev 功能面。

修复：给 contributionIds 一个专属更窄的匹配策略（`app/excluded-surface-policy.ts` 的 `ExcludedIdPattern.appliesToContributions`）——只保留「AI/Chat/Agent/Copilot/MCP/language-model」类（这正是该维度被引入的唯一目的：抓 `SCMHistoryItemContextContribution` 这类无 telltale 命令的 AI 贡献，真实上游 id 已确认为 `workbench.contrib.chat.scmHistoryItemContextContribution`），**不对 contributionIds 套用** extensions/gallery/marketplace、remote、notebook/tasks/testing 三类（对上述 7 个真实 id 逐一验证过不再误判）；这三类在 commandIds/viewContainerIds/viewIds 三个用户可见维度上照原样强制，覆盖未降低（补了对应单测锁定）。auth/sync 两类判断：检索本项目实际依赖树（`package.json` + 已安装 `node_modules/.pnpm`）确认**没有** authentication-service-override / user-data-sync-service-override 包，contributionIds 命名空间里目前不存在类似 `*ExtensionPoint` 的合法惰性管道会撞上这两类正则，故保留这两类对 contributionIds 生效（零已知代价，且保留了「捕获无 chat 字样的 AI 关联 auth/sync 贡献」这个原始意图）；若未来引入上述任一 override 包需重新核实。

### 决策 3：Rust git 域 + 硬化 exec

- 新建 `src-tauri/src/git/`：受限 exec 封装（参数数组、环境净化、无 shell）；后台自动读固定叠加 `GIT_OPTIONAL_LOCKS=0`、`-c core.hooksPath=<空>`、`-c core.fsmonitor=`、`--no-ext-diff --no-textconv`、`GIT_TERMINAL_PROMPT=0`、`GIT_ASKPASS=<拒绝>`、`LANG/LC_ALL=en_US.UTF-8`、超时/输出上限/取消。所有 git 子进程入口先 `require_trusted`（未信任/EMPTY 结构化拒绝，绝不 spawn）。用户显式写/网络操作才放行 hooks/filters/credential/SSH。
- 命令集（F080）：status(`--porcelain=v2 -z --branch`)、diff(`[--cached] --no-textconv --no-ext-diff -- <path>`)、hunk stage(`hash-object`+`update-index`)、整文件 stage/unstage(`add`/`reset`)、commit(`--file -`)、discard(`checkout -q --`)、fetch/pull/push（预览 + 确认）。porcelain v2/NUL 解析器 locale 无关。
- Harness：修 spawn guard 文案为 git 受限封装；新增 git2/gix 机器禁令；git 命令闭集/硬化参数常量锁定。

### 决策 4：前端 PlainScmProvider

- `PlainScmProvider implements ISCMProvider`：Rust `git_status` DTO → 两个 `ISCMResourceGroup`（Working Tree/Staged）；commit 输入框绑 `ISCMInput`；`getOriginalResource(uri)` 返回 `git:` 只读 scheme（自建 `ITextModelContentProvider` 取 HEAD/index blob，同 `plain-workspace:` 只读 provider 套路）。gutter quick-diff 经 `IQuickDiffService.addQuickDiffProvider`（渲染是 Workbench 既有能力）。并排 diff 用 Monaco 核心。

3. **S2 SCM override 引入 + PlainScmProvider**：第 5 份 AI 剥离 patch（决策 1）+ SCM viewlet 可达 + PlainScmProvider/资源组接线 + `git:` 只读 provider + commit 输入框；Browser E2E（status 显示、SCM viewlet 无 AI 命令）。

## S1 输出格式实测事实（本地 git 2.50.1，xxd 字节级验证，非凭记忆）

以下是 S1 解析器的直接依据；每条都在临时仓库造出真实情形后用 `xxd` 核对过字节。

- **`-z` 下 rename/copy 行（type `2`）的 `path`/`origPath` 分隔符是 NUL，不是 TAB**（非 `-z` 才是 TAB）。实测 `... R100 a-renamed.txt\x00a.txt\x00`——最易踩的坑，已双重确认。
- **`--numstat -z` 与 porcelain/`--name-status -z` 不是同一套分隔规则**：numstat 记录**内部**字段用 TAB（`added\tdeleted\tpath`）、记录**之间**用 NUL；rename 时 path 字段为空并紧跟 `\0old\0new\0`；二进制为 `-\t-\tpath`。必须写两个独立 tokenizer，不能复用。
- `# branch.upstream`/`# branch.ab` 在无 upstream 时**整行缺失**（不是空值），故建模为 `Option`；detached 时 `# branch.head (detached)`；无提交时 `# branch.oid (initial)`。
- `-z` 隐含关闭路径 quoting，与 `core.quotePath` 无关；文件名可合法含 LF（这正是必须用 NUL 而非 LF 分隔的原因）。三组对照实测：无 `-z` 时非 ASCII 被八进制转义、含 LF 者即使 `quotePath=false` 也仍被转义；加 `-z` 后一律原样裸字节。
- **路径字段必须建模为 `Vec<u8>`**（或允许非法字节的 newtype），仅在展示边界 `from_utf8_lossy`：Linux 文件名是任意字节序列，git 会原样吐非法 UTF-8（macOS APFS 在文件系统层拒绝这类名字，故本机造不出该 fixture，但不能据此假设跨平台安全）。
- 行终止：`-z` 下头部行与每条记录均以单个 NUL 结尾、无 LF、无多余尾随 NUL。
- `<sub>` 字段建议拆成 `is_submodule/commit_changed/tracked_changed/untracked_changed` 四个 bool（实测覆盖 `N...`/`S.M.`/`SC.U`）。
- ignored 行（`! path`）**默认不输出**，需显式 `--ignored`。
- 取版本内容（前端用 Monaco 自算 diff，Rust 只回完整内容）：`git show :<path>`（index）/`git show HEAD:<path>`（HEAD），**路径需加 `./` 前缀**——否则 `-` 开头路径会被误判为 pathspec magic 而报 `Unimplemented pathspec magic`。找不到时 exit 128 且 stderr 有三种可区分文案（`does not exist in 'HEAD'` / `exists on disk, but not in 'HEAD'` / `does not exist (neither on disk nor in the index)`），应映射为「无该版本」而非硬错误。
- locale：本机 Apple Git 未编译 gettext 故测不出消息本地化，但 Linux 发行版 git 通常编译了 i18n——S0 强制 `LANG/LC_ALL=en_US.UTF-8` 的防御必须保留。

S1 测试边界清单（均已实测可复现）：干净仓库/有无 upstream/ahead-behind 组合/detached/`MM` 双改/`A.`/`.T` type change/三种删除语义/rename/copy（需 `status.renames=copies` 且源同时被改）/`2 RM` 复合/`UU` 冲突/untracked/ignored/子模块四态/路径含空格·LF·非 ASCII/`-` 开头路径/`git show` 三种找不到文案/numstat 二进制与 rename 空 path 占位。
